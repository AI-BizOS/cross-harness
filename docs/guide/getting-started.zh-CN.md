# 第一次使用

[English](getting-started.md) · [指南目录](README.zh-CN.md)

下面用终端界面演示。[网页界面](interfaces.zh-CN.md#网页界面)的用法相同，只是换成按钮。

## 1. 打开项目

```sh
cd 你的项目
cross-harness
```

cross-harness 在至少有一次提交的 git 仓库里效果最好：每个代理都有自己的 worktree 和分支。在普通目录里，代理共用这个目录。

欢迎页列出 cross-harness 找到的代理。如果少了你期望的那个，在另一个终端运行 `cross-harness detect` 看看。

## 2. 发送消息

每行以你想要的代理开头：

```
@bizos 修复 src/parser 里失败的测试
@codex 为 parser 补充边界测试；错误格式不清楚就问 bizos
```

每一行是一个独立的任务，几个代理同时开始。`@codex @claude 审查 src/` 则让两个代理做同一件事。给新代理的第一条消息会稍慢一点：cross-harness 要为它创建 worktree，代理也要启动自己的会话。

## 3. 回答代理的请求

代理要做当前权限模式不允许自动进行的事（比如运行命令）时，会等你决定。按 `a` 查看所有等待中的请求：

- **允许一次**：只放行这一次。
- **以后都允许 @代理 这样做**：这个代理以后再运行同一条命令时自动放行；用 `;`、`&&`、管道或重定向接在后面的命令不算在内。
- **拒绝**：代理会得到拒绝并继续工作。

代理也可能请你做决定，这些问题也在同一个地方等你。

## 4. 观察和引导

用 `↑ ↓` 或 `1`–`9` 选中代理，可以看到它的对话、运行的命令和修改的文件。代理工作时再发一条消息就能引导它；`s` 让它停下。

## 5. 审查与合并

按 `d` 查看选中代理在自己分支上的改动，再按 `m`：

1. **先让另一个代理审查（推荐）**：另一个代理阅读 diff，最后给出 PASS 或 FAIL。
2. **不审查直接合并。**

cross-harness 以 `--no-ff` 合并到你所在的分支，并保留代理的分支。项目有未提交的改动时拒绝合并；出现冲突时干净地中止。
